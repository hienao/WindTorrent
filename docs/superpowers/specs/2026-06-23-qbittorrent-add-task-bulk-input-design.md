# qBittorrent 添加任务批量输入设计

- 日期：2026-06-23
- 状态：对话中已确认，可进入实现计划阶段
- 范围：`lib/features/add_task/presentation/pages/add_task_page.dart` 及 qBittorrent 默认保存路径相关接线

## 概述

更新“添加任务”页面：当用户选择的下载器为 `qBittorrent` 时，链接输入区域切换为更适合批量粘贴磁力链接的输入模式。该模式下，页面需要提供更大的多行输入框，明确提示“每行一个磁力链接”，并在保存路径输入框为空时，使用当前所选下载器的默认保存路径作为动态提示文案。

本次改动只针对 `qBittorrent`。其他下载器继续保持现有单行输入体验，不在这次改动中扩展多行批量提交能力。

## 目标

- 让 `qBittorrent` 的添加任务体验更适合批量录入磁力链接。
- 保持当前页面主流程不变，不重做整页结构。
- 在用户输入保存路径前，先展示当前下载器的默认保存路径。
- 切换下载器时，保护用户已经手动输入的保存路径。
- 严格控制改动范围，只处理 `qBittorrent`。

## 非目标

- 不为 Aria2 或 Transmission 增加多行批量 URL 输入支持。
- 不重做下载器选择器、来源卡片布局或底部操作栏。
- 不把粘贴后的链接转换成标签、卡片或结构化块。
- 不自动把默认保存路径写入保存路径输入框。
- 不把这次改造成通用的“按下载器定制表单引擎”。

## 当前上下文

当前“添加任务”页面无论选中哪种下载器，都复用同一套链接输入框；保存路径输入框也只使用固定的“默认保存路径”提示文案。页面本身已经会根据下载器类型展示不同图标和视觉信息，因此基于下载器类型切换输入形态，符合现有交互模型。

当前 `AddTaskRequest` 仍将链接来源建模为单个 `String? url`。而 qBittorrent 的 API 支持在同一个 `urls` 字段中通过换行分隔多个链接，因此 UI 仍可保持纯文本输入方式，在提交前做一次轻量归一化即可。

## 选定方案

本设计采用已确认的 `B. 聚焦输入模式`。

### 布局

- 当所选下载器为 `qBittorrent` 时，链接输入区成为页面的视觉中心。
- 在输入区上方增加一条简短提示文案，例如“qBittorrent 模式：一行一个磁力链接”。
- 输入控件从当前单行样式切换为明显更大的多行文本输入区，默认可见高度约为 4 到 6 行。
- 保存路径区域仍然放在来源区域下方，保持页面主流程与现在一致。
- 对非 `qBittorrent` 下载器，页面继续保持当前单行链接输入样式。

### 保存路径展示

- 保存路径输入框仍然允许用户自由编辑。
- 当保存路径输入框为空时，其 `hint` 需要根据当前下载器状态动态变化：
  - 已成功读取到默认路径时，显示该默认路径
  - 正在读取默认路径时，显示加载中的提示文案
  - 无法读取默认路径时，回退为当前通用提示文案
- 本次改动要求使用动态 `hint` 展示默认保存路径，不要求额外增加单独的辅助说明行。
- 默认保存路径只用于展示，不自动写入输入框内容，直到用户主动输入。

## 交互规则

### 下载器切换

- 切换到 `qBittorrent` 时，立即启用多行批量输入模式。
- 从 `qBittorrent` 切换到其他下载器时，恢复当前单行输入表现。
- 切换下载器时，已输入的链接文本必须保留。
- 切换下载器时，用户已手动输入的保存路径必须保留。

### 保存路径更新

- 选中下载器后，页面触发一次该下载器默认保存路径的读取。
- 读取结果只更新 `hint` 展示，不修改输入框实际文本值。
- 如果用户已经输入保存路径，后续切换下载器时不得覆盖该内容。
- 如果默认路径读取失败，页面仍允许正常提交，仅回退到通用保存路径提示文案。

### qBittorrent 链接输入

- qBittorrent 模式保持纯文本编辑体验。
- 批量粘贴多个磁力链接时，需要保留换行。
- 用户可以直接查看和修改原始文本，不做结构化拆分。
- 提交前会忽略空行。

### 非 qBittorrent 链接输入

- Aria2 和 Transmission 保持现有单行输入体验。
- 本次改动不为非 qBittorrent 下载器增加批量提交行为。
- 即使用户在非 qBittorrent 状态下粘贴了多行内容，页面也不切换到 qBittorrent 的批量输入态。

## 数据流

### 默认保存路径读取

1. 页面先解析当前选中的下载器。
2. 当选中下载器发生变化时，页面请求该下载器的默认保存路径。
3. 请求结果更新为页面内部的瞬时视图状态：
   - `加载中`
   - `已解析路径`
   - `不可用`
4. 保存路径输入框根据这份状态计算当前展示的 `hint` 文案。

### 提交前归一化

1. 页面读取当前链接输入框中的文本。
2. 如果当前下载器是 `qBittorrent`，则在提交前做一次归一化：
   - 按换行拆分
   - 去掉每行首尾空白
   - 移除空行
   - 再用 `\n` 拼接剩余内容
3. 归一化后的结果沿用现有提交流程继续向下传递。
4. 非 qBittorrent 下载器继续走当前提交路径。

## 状态模型

本页需要维护一组独立于文本控制器之外的瞬时 UI 状态：

- 当前所选下载器是否为 `qBittorrent`
- 当前所选下载器默认保存路径的加载状态
- 当前所选下载器已解析出的默认保存路径文本（如有）

这组状态暂时保留在页面内部即可，因为它与当前页面展示和交互时机强相关，暂时没有必要单独抽成新的控制器。

## 错误处理

- 默认保存路径读取失败不能阻塞页面渲染。
- 默认保存路径读取失败不能阻塞任务提交。
- 如果 qBittorrent 默认保存路径读取失败，UI 只能回退到通用提示文案，不能伪造路径。
- 提交前归一化只允许去除空行和每行首尾空白，不应额外改写非空内容。

## 测试策略

### 组件测试

- 选中 `qBittorrent` 下载器时，页面显示批量输入提示文案和多行输入框。
- 选中非 qBittorrent 下载器时，页面保持当前单行输入表现。
- 所选下载器默认路径读取成功后，保存路径 `hint` 会更新。
- 默认路径读取过程中，保存路径 `hint` 显示加载态文案。
- 用户手动输入的保存路径在切换下载器后仍然保留。
- 链接文本在切换下载器后仍然保留。

### 单元测试

- qBittorrent 链接归一化会移除空行，并保留非空链接之间的换行分隔。
- 非 qBittorrent 提交流程不会误用 qBittorrent 的多行归一化逻辑。
- 默认保存路径读取的接线逻辑能正确处理成功和失败状态。

## 实现备注

- 尽量复用当前页面结构和现有新拟态组件，不引入新的页面布局体系。
- qBittorrent 模式的视觉变化要足够明显，不能只是“默认输入框稍微变高一点”。
- 默认保存路径接口建议优先走 qBittorrent 专用能力。如果同时可用 `/api/v2/app/defaultSavePath` 和 `/api/v2/app/preferences`，优先接专门的默认路径接口。

## 已确认决策

- 采用 `B. 聚焦输入模式`
- 多行批量输入只支持 `qBittorrent`
- 默认保存路径只作为 `hint` 展示，不自动写入输入框
- 切换下载器时不能覆盖用户已输入的保存路径
