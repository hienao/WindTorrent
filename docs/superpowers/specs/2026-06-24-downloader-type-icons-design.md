# 下载器类型图标设计

日期：2026-06-24
状态：已在对话中确认，待实现

## 摘要

WindWalker 目前在以下三个位置，对下载器类型图标使用了不一致的表现方式：

- 管理页中的下载器卡片
- 添加任务流程中的已选下载器卡片与下载器选择列表
- 概览列表中的下载器小图标

本次设计要把这三处统一到同一条规则下：

- 外层容器风格由 WindWalker 自己定义
- 内部符号允许尽量贴近各下载器官方 App 的识别形象

最终效果应该让用户感觉这是一套属于同一个产品的图标体系，同时又不削弱 Aria2、qBittorrent、Transmission 的第一眼识别度。

## 目标

- 让三种下载器类型在扫一眼时就能区分出来。
- 让同一种下载器在大、中、小三种尺寸下保持同一身份识别。
- 复用同一个共享组件，避免下载器卡片、添加任务页面、概览列表再次各画各的。
- 尽量保留与官方 App 的联想，尤其是 qBittorrent 和 Transmission。

## 非目标

- 不修改底部导航栏中的“下载器”Tab 图标。
- 不直接引入外部位图资源作为应用内图标。
- 不追求对第三方官方商标图标做到像素级原样复制。

## 当前问题

当前代码里混用了多种图标策略：

- `lib/features/home/presentation/widgets/neo_downloader_widgets.dart` 中有自定义品牌化图标块
- `lib/features/add_task/presentation/pages/add_task_page.dart` 中使用 Material Icon 映射
- `lib/features/home/presentation/widgets/neo_overview_widgets.dart` 中使用通用 `storage` 图标

这会带来两个问题：

1. 同一个下载器在不同页面看起来像不同东西。
2. 图标丢失了下载器自身的协议/品牌识别，尤其是在退化成通用 Material 图标之后。

## 已确认方向

采用混合方案：

- 外层形状、留白、圆角、阴影归 WindWalker 统一管理。
- 内部图形使用向量绘制，并允许尽量贴近每种下载器的公开参考图。
- 小尺寸版本可以删减细节，但不能改变主轮廓。

这个方向已经在对话中被明确确认。此前更抽象、几何化更强的方案已经被否掉。

## 共享视觉系统

### 共享容器

三种下载器图标都应该使用同一套容器家族：

- 圆角方形图标底座
- 与当前 UI 一致的拟物 / 柔和浮起表面
- 圆角半径随尺寸变化，但规则一致
- 内边距和视觉居中规则一致

推荐的尺寸场景：

- 大号：下载器管理卡片主图标
- 中号：添加任务页已选下载器卡片、下载器选择列表
- 小号：概览行、小型列表入口

容器可以带有类型色彩倾向，但容器结构本身不能因为下载器类型不同而变化。

### 共享尺寸层级

同一套图标体系至少需要支持以下三个层级：

- 大图标：管理卡片主图标
- 中图标：添加任务页卡片与选择列表
- 小图标：概览行

规则：

- 尺寸越小，只删纹理和细小高光
- 不允许在尺寸切换时改变主轮廓识别

## 各类型图标规范

### Aria2

方向：

- 保留已确认的 “A + 2” / 字标式识别，不强行改成过于抽象的几何符号。
- 相比另外两个下载器，保留 Aria2 更轻、更干净的气质。

必须具备的特征：

- 蓝 / 青色系主色倾向
- 能一眼读出 Aria2 联想的字标，或明显的 `A` + `2` 结构
- 明确区别于 qBittorrent 那种蓝色 App 方块风格

不要做的事情：

- 不要把 Aria2 降级成通用下载箭头
- 不要几何化到看不出 Aria2 联想

原因说明：

这是基于公开视觉使用方式做出的推断：Aria2 的公开识别并不像 qBittorrent 或 Transmission 那样稳定锚定在某一张统一的 App 图标上，因此保留字标式识别，比强行做成严格对称图标更重要。

### qBittorrent

方向：

- 高保真贴近用户指定的 qBittorrent Alt macOS Big Sur 参考图轮廓。
- 图标要尽量做到“一眼看过去就像那张参考图”。

主要公开参考：

- [qBittorrent Alt macOS Big Sur](https://icon-icons.com/icon/qbittorrent-alt-macos-bigsur/189495)

必须具备的特征：

- 蓝色圆角方形 App 面
- 从上偏亮到下偏深的蓝色渐变
- 白色管状 `qb` 一体化字形，作为视觉主体
- `qb` 必须被感知成一个整体 App 图形，而不是两个临时拼出来的字母

不要做的事情：

- 不要把它重新解释成抽象条形、圆圈或通用符号
- 不要把 `q` 和 `b` 拆成两个松散的独立字形再拼起来
- 不要让右边看起来像悬空的 `D` 或断开的竖干

实现意图：

- 直接按参考图的整体白色 `qb` 轮廓重绘向量形状
- 小尺寸时只删掉次要高光细节，不改主轮廓

### Transmission

方向：

- 高保真贴近用户指定的官方 Transmission App 图标结构。
- 保留强烈的 “T 把手 + 向下箭头” 识别。

主要公开参考：

- [Transmission 官方图标](https://transmissionbt.com/assets/images/Transmission_icon.png)

必须具备的特征：

- 金属灰色纵向 T 型结构
- 顶部红色握把 / 横杆
- 中间居中的深色向下箭头
- 在共享 WindWalker 容器体系内保留浅色 App 面

不要做的事情：

- 不要把 Transmission 压扁成泛化的红色三角或普通下载图标
- 不要去掉顶部握把与箭头杆之间的 T 型关系

实现意图：

- 中号和大号尺寸尽量保留官方结构
- 小尺寸只去掉细碎纹理，不改变整体识别

## 跨页面映射

同一个共享下载器类型图标组件需要被以下位置统一使用：

- `lib/features/home/presentation/widgets/neo_downloader_widgets.dart` 中的 `NeoDownloaderCard`
- `lib/features/add_task/presentation/pages/add_task_page.dart` 中的已选下载器卡片和下载器选择行
- `lib/features/home/presentation/widgets/neo_overview_widgets.dart` 中的概览下载器行

预期变更：

- 用一个共享的下载器类型图标入口，替换各页面本地分散的图标逻辑

## 可访问性

- 图标不能只靠颜色区分，灰度环境下也要尽量能靠形状识别。
- 形状识别在低对比度下仍应尽量成立。
- 语义仍以文本为主；除非现有组件本身已经赋予图标语义，否则图标默认按装饰性处理。

## 测试与验收关注点

- 在浅色和深色主题下检查三种尺寸层级的视觉效果
- 验证 qBittorrent 在小尺寸下仍然能读出 `qb`
- 验证 Transmission 在小尺寸下仍然能读出 “T 把手 + 向下箭头”
- 验证 Aria2 即便同属蓝系，也不会和 qBittorrent 混淆
- 确保三处页面真正使用的是同一个组件或同一套绘制来源

## 本次实现不包含

- 不重做下载器状态 Badge
- 不重做整个管理卡片布局
- 不修改非下载器相关的功能图标

## 验收标准

- 管理页、添加任务流程、概览列表三处都展示同一套下载器类型图标体系。
- qBittorrent 明显贴近已确认的 Alt Big Sur 参考方向。
- Transmission 明显贴近已确认的官方 App 图标方向。
- Aria2 保留已确认的字标式识别，而不是退化成通用下载符号。
- 任何页面都不再退回到 `Icons.storage_*`、`Icons.downloading_*`、`Icons.file_download_*` 这一类通用 Material 图标来表示下载器类型。
